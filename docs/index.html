Predicting Content Performance Across Unseen Clients

A public-safe machine learning study using aggregated content-performance signals

1. Abstract

This study asks whether aggregated content-performance features can provide useful predictive signal for clicks over a 90-day window when evaluated on previously unseen clients. A Random Forest regression model was trained using public-safe aggregated features and evaluated using a client-grouped validation design against a simple mean-prediction baseline. On the grouped test split, the Random Forest achieved an MAE of 1.134, RMSE of 23.509, and R² of 0.867, compared with baseline MAE of 21.592, RMSE of 64.622, and R² of -0.007. These measured results indicate useful predictive signal within the available evaluation setup, while remaining subject to temporal leakage risk and other dataset limitations. The resulting signals were also converted into a ranked human-review action playbook for decision support rather than automatic content changes.

2. Introduction / Problem Statement

Content teams often need to decide which pages deserve attention first. A large content inventory makes manual prioritization difficult, particularly when performance varies across clients and pages.

This project investigates whether aggregated content-performance metrics can provide a useful predictive signal for clicks_90d. The practical decision supported by the analysis is whether model-based signals can help prioritize content for human review.

The project deliberately frames the result as decision-support evidence. Predictive association is not treated as proof of causation or guaranteed business improvement.

3. Data

The analysis used the FlyRank ML Internship dataset and the pseudonymized warehouse release flyrank_pseudonymized_warehouse_release_v20260703, with a snapshot export date of 2026-07-03.

The broader release contains four tables: dim_clients, dim_content, fact_content_daily_performance, and fact_content_query_90d. The daily performance table contains approximately 79 million rows in the release.

The modeling work used the provided anonymized starter dataset containing 30,000 rows and 44 columns. The analysis used aggregated trailing-90-day performance measures and content attributes.

Client names, URLs, page-level identifiers, and private search queries were excluded from the public-facing analysis. Label-derived or leakage-prone fields were also excluded from the model feature set.

4. Methodology

Features

The final model used:

  • impressions_90d
  • sessions_90d
  • content_age_days
  • avg_position
  • ctr
  • trend_pct

Label

The prediction target was clicks_90d.

Model

A Random Forest regression model was used as the primary model. The model was compared with a simple mean-prediction baseline that predicts the training-set mean for every test observation.

Validation Design

The final evaluation used a client-grouped split. Clients in the test set were not included in the training set, making the evaluation more demanding than a random row-level split and more relevant to cross-client generalization.

Metrics

Performance was measured using Mean Absolute Error (MAE), Root Mean Squared Error (RMSE), and R-squared (R²).

Leakage Checks

A feature leakage audit identified fields derived from labels or closely related to the target and excluded them from the model. However, the exact temporal alignment of all rolling aggregate windows cannot be reconstructed from the starter dataset, so temporal leakage cannot be fully ruled out.

Interpretation

On this grouped validation split, the Random Forest produced substantially lower MAE and RMSE than the mean-prediction baseline and a substantially higher R². This indicates that the selected aggregated features contained useful predictive signal within this evaluation setup.

These are measured results from the available dataset and validation design. They should not be interpreted as proof of causal impact, guaranteed business improvement, or production-ready performance.

6. Limitations & Honest Framing

Temporal leakage risk

Rolling aggregate features make it difficult to reconstruct the exact temporal relationship between feature windows and the target window. Therefore, complete elimination of temporal leakage cannot be claimed.

Generalization

Client-grouped validation tests performance on clients not seen during training, but the result still comes from the available anonymized dataset. It does not establish performance on every future production environment.

No causal claim

Predictive relationships do not demonstrate that changing a feature or applying a recommendation will cause clicks to increase.

Aggregated data

Public-safe aggregation protects confidentiality but limits detailed page-level investigation.

Human review

Recommendations are prioritization guidance. A human should review the evidence before making content changes.

7. Ranked Recommendations

The action playbook converts observed performance signals into a ranked review queue. The final actionable queue contained 12,517 items.

Rank Action Queue Size Purpose
1 SNIPPET_TITLE_REVIEW 5,509 Review titles and search-result snippets.
2 FRESHNESS_CHECK 2,931 Review content freshness and possible updates.
3 FULL_CONTENT_AUDIT 2,066 Perform broader content review when multiple signals are present.
4 REFRESH_REVIEW 2,011 Review older or declining content for possible refresh.

Recommended Workflow

  1. Start with the highest-priority items.
  2. Review the supporting signals and reason codes.
  3. Apply human judgment before making changes.
  4. Record decisions and outcomes for future monitoring.
  5. Re-evaluate the ranking approach when new validation data becomes available.
